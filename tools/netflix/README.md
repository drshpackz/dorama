# Конвейер данных «Netflix Топ-10»

Собирает из файлов Netflix Top 10 папку `netflix/` (GitHub Pages), которую читает плагин `netflix.js`.
Контракт файлов — §3 спецификации `docs/superpowers/specs/2026-11-12-netflix-plugin-design.md`, задачи — §12.
Python 3.9+, только стандартная библиотека.

## Файлы

| файл | что делает |
|---|---|
| `fetch.sh` | качает три TSV Netflix в `.nf/` (curl, User-Agent Chrome 142, GET) |
| `fetch_www.py`, `www-sources.json` | качает отчёты What We Watched в `.nf/` (подсказки сопоставлению: оригинальные названия, даты выхода) |
| `pipeline.py` | вход: проверка TSV → тайтлы → правки `split` → TMDB → остальные правки → номера → файлы |
| `nfdata.py` | разбор TSV и xlsx, тайтлы и сезоны, тёзки |
| `ids.py` | стабильные номера `n` и `sid` (`state/ids.json`) |
| `aggregates.py` | поля строки тайтла §3.3 |
| `tmdb.py` | клиент TMDB (ключ только из `TMDB_API_KEY`, ≈ 8 запросов/с, повторы на 429/5xx, бюджет) и кэш |
| `matcher.py` | сопоставление (матчер v4 прототипа r3) и выбор работы на запуск |
| `trailers.py` | строка трейлеров `tr` (§3.4) |
| `publish.py`, `validate.py` | запись файлов и инварианты §3.9 |
| `overrides.json` | ручные правки |
| `state/ids.json` | номера; правится только руками в одном случае (см. «Слияния») |
| `state/tmdb.jsonl` | кэш TMDB: строка на ключ тайтла, по алфавиту |
| `state/review.json` | очередь на ручное решение, генерируется |

## Запуск

```sh
cd /Users/m1/dorama
bash tools/netflix/fetch.sh .nf
python3 tools/netflix/fetch_www.py --dest .nf
python3 tools/netflix/pipeline.py --src .nf          # без TMDB_API_KEY: карточки только из кэша и правок
python3 tools/netflix/validate.py --out netflix --state tools/netflix/state
```

По умолчанию `--state tools/netflix/state`, `--overrides tools/netflix/overrides.json`, `--out netflix`. Конвейер
печатает таблицу размеров против бюджета §3.10 и долю тайтлов индекса с TMDB id и трейлером. Повторный запуск на том
же входе ничего не пишет. При плохом входе или нарушенном инварианте он выходит с ошибкой и не трогает `netflix/`.

Флаги: `--no-tmdb` — без запросов к TMDB; `--tmdb-budget N` — запросов за запуск (по умолчанию 600, с `--backfill` без
предела, 0 — без предела); `--backfill` — сопоставить все ещё не сопоставленные тайтлы, глобальные первыми.

## Ключ TMDB

Ключ берётся только из переменной окружения `TMDB_API_KEY`: ключ API v3 (32 знака) или токен чтения v4 (длинный,
`eyJ…`) — подходят оба. По решению владельца (12.11.2026) это ключ, встроенный в сам Lampa
(`/tmp/lampa-source/src/core/tmdb/tmdb.js`, `Lampa.TMDB.key()`); им один раз заполнена вся база на m1, кэш
`state/tmdb.jsonl` лежит в репозитории.

На GitHub секрета нет, и он не нужен: еженедельная сборка идёт как с `--no-tmdb`, тайтлы прошлых недель берут
TMDB из кэша, а новые тайтлы недели приходят заглушками (`id` null). Их находит сам плагин на ТВ через
встроенный в Lampa TMDB (`fillStubs` в `netflix.js`) и запоминает в Storage `netflix_stub_tmdb`. Если когда-нибудь
понадобится дозаполнить кэш здесь — та же команда `--backfill` с ключом Lampa на m1 и коммит `tools/netflix/state/`.

### Первичное заполнение (сделано 12.11.2026 на m1)

```sh
cd /Users/m1/dorama
bash tools/netflix/fetch.sh .nf
python3 tools/netflix/fetch_www.py --dest .nf
TMDB_API_KEY='<ключ>' python3 tools/netflix/pipeline.py --src .nf --backfill
python3 tools/netflix/validate.py --out netflix --state tools/netflix/state
```

- Это ≈ 26 тыс. запросов (поиск en-US и details ru-RU с роликами и ключевыми словами), около часа при 8 запросах в
  секунду. Сначала идут id из правок, затем глобальные тайтлы, затем местные по убыванию очков.
- Кэш сохраняется каждые 250 тайтлов. Ctrl-C сохраняет его и выходит; та же команда продолжает с места остановки.
- В конце строка `TMDB in the index: id … %, trailers … %`: цель — id у ≥ 95 % строк индекса, трейлер у ≥ 80 %.
- Затем — очередь `state/review.json` (ниже) и коммит `netflix/` и `tools/netflix/state/`.

После заполнения каждая еженедельная сборка с ключом:
1. ищет новые тайтлы — сначала тайтлы последней недели;
2. раз в 30 дней обновляет карточки тайтлов последней недели (постер, русское название, трейлеры появляются позже);
3. один раз перезапрашивает карточки, чьи трейлеры выбраны по старым правилам (`trv` в строке кэша меньше
   `trailers.VERSION`; версия 2 — флаг `s` у роликов с субтитрами в кадре): сначала русские ключи и английские ключи
   тайтлов не на английском, тайтлы последней недели первыми, дальше по очкам;
4. раз в месяц заново ищет то, что было `low` и `none`.

Всё это в пределах `--tmdb-budget`. Пункт 3 — ≈ 8 500 запросов: чтобы не растягивать его на 15 недель по 600,
один запуск с ключом и `--tmdb-budget 0` (≈ 20 минут), затем коммит `netflix/` и `tools/netflix/state/`.

## Правки — `overrides.json`

Ключ — ключ тайтла: `tv:<show_title>` или `film:<show_title>` как у Netflix. У тёзок-фильмов более поздний фильм
получает хвост: `film:Alpha#n2.35`. Ключи всех тайтлов — в `state/ids.json`. Строки с ключом на `_` и поле `why` —
заметки.

| операция | пример | что делает |
|---|---|---|
| `tmdb` | `{"tmdb": "tv/136125"}` | карточка этого id TMDB, `cf = 3`; поиск не идёт, details берутся по id |
| | `{"tmdb": null}` | без карточки: заглушка с названием Netflix |
| `hide` | `{"hide": true}` | не искать в TMDB, не держать в очереди и в «местных хитах»; в чартах тайтл остаётся заглушкой |
| `split` | `{"split": [{"countries": ["KR"], "from": "2025-01-01", "tmdb": null}, {"tmdb": "movie/419478"}]}` | делит строки одного ключа на разные тайтлы |
| `merge` | `{"merge": "tv:Monster"}` | слить с другим ключом: остаётся меньший `n` |
| | `{"merge": false}` | никогда не сливать этот ключ (отмена слияния по TMDB id) |
| `ru` | `{"ru": "Клуб"}` | своё русское название |
| `tr` | `{"tr": "ru:T:1kwgRyiNUYg en:T:oqxAJKy0ii4"}` или `{"tr": ""}` | свои трейлеры (§3.4) или «трейлера нет» |
| `lv` | `{"lv": 1}` | прямой эфир или спорт: вне тайтловых списков по умолчанию |

`split`:
- Строка чарта уходит в первую часть, у которой выполнены `countries` и период. Период — `from` и `to`, даты
  воскресенья недели.
- Последняя часть забирает всё остальное и сохраняет ключ и его номер. Часть i перед ней становится ключом
  `<ключ>#<i>`: `film:The King#1`.
- Мировые строки и строки «за всё время» страны не имеют, их берут только части без `countries`.
- В части можно задать `tmdb`, `ru`, `tr`, `lv`, `hide`. Остальные операции ключа относятся к последней части.

Сейчас в файле правки из r3 §4.4: The Club → `tv/136125` (турецкий «Kulüp»), Face to Face → `movie/1146759`, The King
и Midnight Sun разделены по странам, The Rise of Igbinogun скрыт.

## Очередь — `state/review.json`

- `unmatched` — тайтлы, которые TMDB не сопоставил уверенно (`low`) или не нашёл (`none`), по убыванию очков `pts`.
  У них карточки нет. В строке:
  - ключ, `n`, недели, недели в мировом топе `gw`, страно-недели `cw`, главные страны;
  - для `low` — лучший кандидат `cand` (оценка, id, название, год, язык) и ещё до трёх `alts`.
- Как решать: строка в `overrides.json` — `{"tmdb": "movie/<id>"}`, `{"tmdb": null}` или `{"hide": true}`. Править
  стоит глобальные и многострановые тайтлы сверху очереди (r3: 100–150 правок). Однострановые хиты на 1–2 недели
  можно оставить заглушками.
- `merges` — карточки, слитые из нескольких ключей:
  - `by: tmdb` — по общему TMDB id, например сезоны-антологии под разными названиями;
  - `by: override` — правкой `merge`.

  Проверить глазами. Неверное слияние: `"<ключ>": {"merge": false}` и при нужде верный `tmdb` этому ключу.
- `pending` — сколько тайтлов ещё ни разу не искали: нет ключа или кончился бюджет.

### Слияния и номера

- Номера `n` и `sid` не меняются между сборками. Новые получают следующий свободный номер.
- При слиянии остаётся меньший `n`. Слияние записывается в `state/ids.json` → `merged` и держится, пока его не
  отменит `{"merge": false}`.
- После `split` последняя часть сохраняет номер ключа, остальные части получают новые.

## Еженедельная сборка — `.github/workflows/netflix-top10.yml`

- Вторник 21:00 UTC и среда 07:00 UTC (повтор): Netflix выкладывает неделю во вторник около 19:55 UTC.
- Шаги: `fetch.sh` и `fetch_www.py` → сравнение последней недели TSV с `netflix/manifest.json` → если неделя та же,
  работа кончается без сборки и коммита («нет новой недели») → `pipeline.py` → коммит `netflix/` и
  `tools/netflix/state/`, только если что-то изменилось.
- Плохой вход: страница вместо TSV, неполные недели, неделя меньше опубликованной, индекс меньше на 1 % и больше.
  Тогда шаг падает, старые файлы остаются, GitHub присылает письмо.
- Без секрета `TMDB_API_KEY` сборка идёт с `--no-tmdb`.
- Ручной запуск (Actions → Netflix Top 10 data → Run workflow):
  - `force` — собрать на той же неделе, например после правки `overrides.json`;
  - `backfill` и `tmdb_budget` — заполнение TMDB на GitHub. Для полного заполнения поставить `tmdb_budget` = 0:
    около часа, лимит задания 120 минут.
- Запасной путь, если Netflix не отдаёт файлы раннерам GitHub: те же команды по cron на m1 и `git push`.

## Проверить после первой выкладки

```sh
curl -sI -H 'Accept-Encoding: gzip' https://drshpackz.github.io/dorama/netflix/index.json \
  | grep -iE '^(HTTP|content-encoding|access-control-allow-origin|content-length)'
```

- Сжимает ли Pages `.json`: есть ли `content-encoding: gzip`. Если нет, плагин качает `index.json` целиком,
  ≈ 0,67 МБ, раз в неделю.
- Есть ли `access-control-allow-origin: *`.

Результат: не проверено, данных на Pages ещё нет.
